# Repo cleanup + content-descriptive fixture naming

**Date:** 2026-05-27
**Status:** Approved (pending spec review)
**Base branch:** `main` (independent of the unmerged `feat/inventory-fingerprint` stack)

## Problem

The repo has accumulated cruft and undescriptive fixtures:

1. **Root artifacts.** `Sample Document.repaired.docx` (a tracked, regenerable repair output) and `package-lock.json` (an untracked npm lockfile in a bun-only repo) sit in the repo root.
2. **`fixtures/eigen-extended/`.** 151 tracked `.docx` files referenced by _nothing_ in `src/`, `tests/`, or `scripts/`. Names are meaningless (`Untitled Document (71).docx`). Content analysis shows 148 of 151 have distinct `word/document.xml` (only 3 duplicate pairs) — these are genuinely distinct real-world specimens, not redundant copies.
3. **`tests/fixtures/` strays.** Three garbage-named files:
   - `tests/fixtures/vfdsdfcACawesd.docx` (random name; referenced only by a doc-comment in `fixtures-all-strict.test.ts`)
   - `tests/fixtures/word-strict/second-pass/Ouch.docx`
   - `tests/fixtures/word-strict/tests:fixtures:broken:sample-document.broken-tables.docx-repaired.docx` (a relative path accidentally captured as the filename)
4. **`update-manifest.ts` regression hazard.** The fixtures-all manifest is regenerated by walking `tests/fixtures/` and running the validator. It sets each entry's `word` field from `tests/word-probe-results.jsonl`, which no longer exists — so a naive regen silently downgrades every `word` value to `"unknown"`, destroying curated metadata.

## Goals

- Remove root cruft.
- Give every undescriptive fixture a name that **represents its comment or error**, following the established convention `<subject-slug>.<comment-or-error-descriptor>.docx` (see `tests/fixtures/broken/README.md`).
- Fold the eigen-extended specimens into the real, exercised test corpus under `tests/fixtures/`, sorted into existing categories.
- Keep the manifest-driven `fixtures-all-{strict,lenient}` suites green throughout — they are the regression net.

## Non-goals

- No validator/repair logic changes.
- No touching `tests/fixtures/external/` (third-party vendored snapshots) beyond leaving them as-is.
- Not re-running LibreOffice Word probes (`soffice` unavailable here); `word` metadata is preserved, not regenerated.

## Naming convention

`<subject-slug>.<comment-or-error-descriptor>.docx`, kebab-case, derived deterministically from file content:

- **Has validation error(s):** descriptor = primary (alphabetically-first) strict error code, e.g. `table.broken-rels.docx`. Target category: `broken/`.
- **Clean + tracked changes (`w:ins`/`w:del`):** descriptor = `suggesting-<kind>` (`insertions`, `deletions`, `mixed-edits`). Target category: `working/`.
- **Clean + comments (`w:comment`):** descriptor = `comment-<slugified-gist>` from the first comment's text. Target category: `working/`.
- **Clean, plain:** descriptor from dominant structure (`table`, `text-box`, `header-footer`, `plain-paragraphs`). Target category: `working/`.

**Subject slug** is derived from, in order: the document's first heading/title text (slugified, ≤4 words) → else a structural noun (`table`, `document`) . The original `Untitled Document (N)` names carry no signal and are discarded.

**Collisions** are resolved with a numeric suffix (`-2`, `-3`).

## Mechanism: deterministic rename/sort script

A single, testable library derives `{ targetCategory, fileName }` from a docx's content fingerprint. No agents — the logic is pure and unit-tested.

### Content fingerprint (`scripts/fixture-fingerprint.ts`)

Pure function `fingerprint(docxPath) → { strictErrorCodes, lenientErrorCodes, insCount, delCount, commentCount, firstCommentText, tableCount, hasHeaderFooter, hasTextBox, titleText, contentHash }`. Built on the existing `validate()` and `unpack`/xml-helpers. The `contentHash` is `sha256(word/document.xml)` for dedup.

### Name derivation (`scripts/derive-fixture-name.ts`)

Pure function `deriveName(fingerprint) → { category: "broken" | "working", descriptor, subjectSlug }`. Fully deterministic; this is the TDD core.

### Manifest hardening (`scripts/update-manifest.ts`)

Change: when no probe record exists for a path, fall back to the **existing manifest's** `word` value for that path (matched by `relativePath`) instead of `"unknown"`. New paths with neither probe nor prior entry get `"unknown"`. This makes regen idempotent w.r.t. `word` metadata.

## Delivery — stacked PRs (each over its predecessor)

- Delete `Sample Document.repaired.docx` (tracked) and `package-lock.json` (untracked).

### PR 2 (over PR 1) — rename the 3 tests/fixtures strays

## Risks & mitigations

- **Regen wipes `word` metadata** → mitigated by PR 1 hardening (preserve prior values).
- **Rename breaks a hard-coded fixture path in some test** → only `vfdsdfcACawesd` is referenced, and only in a doc-comment; everything else is manifest-keyed and re-derived on regen. A repo-wide grep for each old basename precedes every rename.
- **Auto-derived names collide or read poorly** → numeric-suffix collision handling; names reviewed in the PR diff before commit.
- **Adding real-world broken specimens bloats the curated `broken/README.md`** → provenance appended under a separate "Imported real-world specimens (eigen)" section, not interleaved with the hand-authored synthetic-break table.
