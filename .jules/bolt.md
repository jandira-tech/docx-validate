## 2026-05-22 - Avoid xpath ancestor:: resolution in @xmldom
**Learning:** Using `xpath` (from the `xpath` NPM package) with `@xmldom/xmldom` is extremely slow when querying with the `ancestor::` axis (e.g., `.//w:p[not(ancestor::w:txbxContent)]`). This causes significant performance bottlenecks for large documents because it traverses the tree for every matched element dynamically instead of just caching parent lookups.
**Action:** When complex ancestor exclusions are needed on large node lists, rely on native DOM APIs (`getElementsByTagNameNS`) combined with a fast `parentNode` while loop in JavaScript. This simple rewrite improved paragraph counting performance by nearly 100x.
## 2024-05-22 - Avoid xpath descendant queries in @xmldom
**Learning:** Using `xpath` (from the `xpath` NPM package) with `@xmldom/xmldom` is extremely slow when querying with the descendant (`//`) axis (e.g., `.//w:del//w:t`). This dynamic tree searching traversal scales terribly for large XML files.
**Action:** Replace `xpath` descendant queries with native DOM API calls (`getElementsByTagNameNS`). When replacing `.//` axes inside an already matched parent element context (like `.//w:del//w:t`), iterate over the parents and use `.getElementsByTagNameNS` on them. To exactly match the deduping properties of XPath node sets, collect matched children into a `Set<Node>` rather than appending directly to an array. This reduced test script execution time from ~115ms to ~15ms (a ~7.6x speedup).
