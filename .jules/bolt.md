## 2026-05-22 - Avoid xpath ancestor:: resolution in @xmldom
**Learning:** Using `xpath` (from the `xpath` NPM package) with `@xmldom/xmldom` is extremely slow when querying with the `ancestor::` axis (e.g., `.//w:p[not(ancestor::w:txbxContent)]`). This causes significant performance bottlenecks for large documents because it traverses the tree for every matched element dynamically instead of just caching parent lookups.
**Action:** When complex ancestor exclusions are needed on large node lists, rely on native DOM APIs (`getElementsByTagNameNS`) combined with a fast `parentNode` while loop in JavaScript. This simple rewrite improved paragraph counting performance by nearly 100x.

## 2026-05-22 - Avoid xpath descendant:: resolution in @xmldom
**Learning:** Similar to `ancestor::`, using `xpath` with descendant queries like `.//w:del//w:t` and `.//w:del//w:instrText` inside `@xmldom/xmldom` dynamic queries is very slow because it processes the node tree recursively on each query rather than leveraging native APIs effectively.
**Action:** When searching for specific descendants like `t` and `instrText` inside a specific tag like `del`, avoid `xpath`'s descendant queries (`$$(".//w:del//w:t")`). Instead, use native DOM APIs such as `getElementsByTagNameNS` on the document to find the parent tag, and then call `getElementsByTagNameNS` on those returned nodes to find the child elements, adding them to a `Set` to deduplicate and simulate the xpath exact node-set behavior. This drastically improves execution speed across large documents while preserving identical behavior.
