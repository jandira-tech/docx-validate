## 2026-05-22 - Avoid xpath ancestor:: resolution in @xmldom
**Learning:** Using `xpath` (from the `xpath` NPM package) with `@xmldom/xmldom` is extremely slow when querying with the `ancestor::` axis (e.g., `.//w:p[not(ancestor::w:txbxContent)]`). This causes significant performance bottlenecks for large documents because it traverses the tree for every matched element dynamically instead of just caching parent lookups.
**Action:** When complex ancestor exclusions are needed on large node lists, rely on native DOM APIs (`getElementsByTagNameNS`) combined with a fast `parentNode` while loop in JavaScript. This simple rewrite improved paragraph counting performance by nearly 100x.
## 2026-05-22 - Avoid xpath descendant queries for simple inner elements
**Learning:** Using `xpath` (from the `xpath` NPM package) with `@xmldom/xmldom` to query descendants (e.g., `.//w:del//w:t`) causes severe performance bottlenecks for large documents. The problem is exacerbated because it relies heavily on tree traversal.
**Action:** Replace `xpath` queries with native DOM traversal APIs (`getElementsByTagNameNS`). When replacing a descendant query, iterate over the known namespaces to find the parent element (e.g., `del`), and then query its inner elements using the parent's context and namespace (e.g., `del.getElementsByTagNameNS(ns, "t")`). Use a `Set<Element>` to deduplicate results, replicating XPath's node-set behavior.
